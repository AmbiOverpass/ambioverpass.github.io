Abstract

Text-to-OverpassQL lets users query OpenStreetMap in natural language, yet real requests often leave the area, the object tag, the element type or the spatial constraints unspecified, so one request maps to many executable queries. Many of these queries return empty or identical results, and the ambiguity that matters for the answer is much smaller than the ambiguity of the request text. Existing clarification methods value a question by the interpretations it separates and by its immediate benefit, which spends questions on distinctions with the same result and ends the dialogue before questions that are useful together are asked. To address this gap, we propose AmbiOverpass, an execution-aware clarification framework that executes all candidate queries with one shared database query per candidate area and landmark kind and merges queries with identical results into the result classes of an ambiguity topology. On this topology, exact Shapley values over the ambiguity slots credit each question with its share of the joint gain and define a rule for selecting a question and for stopping. A look-ahead planner then evaluates each action by the expected utility of its Shapley-greedy continuation, with a policy-improvement guarantee. On AmbiOverpass-Bench, with 1,754 planning instances and 254 rewriting cases, AmbiOverpass improves the expected utility on two-landmark requests by 6.5 points over one-step planning and by 12.3 points over information gain on queries, and with three questions it answers at least 21.2 points more requests correctly than consistency-based and LLM-based clarification.

Many Queries, Few Different Answers

A vague request to OpenStreetMap maps to many executable queries, but most of them return empty or identical results. Questions should therefore separate results, not query texts.
